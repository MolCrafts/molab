# HPC Project 与 Asset 共享契约

状态：元数据共享及首批文件共享的实现契约。Project Viewer 不隐含文件访问权限；
Asset Sharing 只修改独立发布副本的权限。

## 进程和身份

统一的集群认证入口将私人请求路由到对应用户的 Workspace Service，将
`/api/sharing/` 请求路由到独立共享服务。每个 Workspace Service 由站点批准的
Open OnDemand、用户服务管理器或用户本人启动，以固定的非 root UID 运行。
Molab 不提供 setuid、sudo、账号代用或跨用户进程启动器。

共享服务使用独立账号，只拥有自身本地控制面数据库。它不挂载私人 Workspace
路由，不发现或启动服务插件，不需要任何用户的 SSH 凭据或 Slurm 执行身份。
Workspace Service 的现有插件只在该用户进程内运行；共享读取不会调用它们。

可信身份来自站点认证代理。代理删除外部 `X-Molab-Subject` 和
`X-Molab-Proxy-Key`，根据已经认证的身份重建它们。后端验证代理密钥；用户服务
额外验证 subject 与启动身份完全一致。网关与每个用户服务使用不同代理密钥。
用户可读自己的服务配置，因此不能把网关代理密钥交给用户服务。

Principal 由不可变的 `(issuer, subject)` 标识，显示名和 Linux 用户名不作为授权
凭据。管理员显式配置 `(principal, cluster, uid)` 绑定。变更、冲突或重用的 UID
不会自动获得旧授权；绑定变更需要单独迁移流程。一个集群内的 UID 只能绑定一个
Principal。`ProjectMetadata.owner` 是说明字段，不参与安全判断。

## 控制面数据

授权和审计保存在管理员指定的持久本地磁盘 SQLite 数据库中，不写入用户
Workspace，不随复制、Git 或 rsync 转移。目录要求 0700，数据库要求 0600。
已知网络文件系统被拒绝，管理员还必须显式确认存储满足本地持久盘契约；
文件系统自动探测不是可靠存储的证明。

数据库模式 v1 包括 Principals、Linux 绑定、发布源、共享 Project、Viewer grants、
指定接收者的邀请、发布版本、分批对象及审计。所有授权变更和对应审计处于同一
事务。未知数据库版本拒绝打开。运行期不做破坏性自动迁移。

来源对象身份是 `(source_id, workspace_id, project_id)`。控制面另分配共享 Project
UUID。重命名保留身份；复制到其他来源不继承分享。Run ID 可以在不同 Experiment
中重复，因此 Run 的身份必须同时包含 Experiment ID；本地选择使用现有 `molab:`
复合引用。

## 发布和刷新

Owner 在私人服务中选择 Project、Experiment、Run、参数名称和数值指标名称，
预览确切内容，再确认发布。确认包含预览摘要；内容在确认前改变时返回 409，要求
重新预览。默认不发布描述、参数或指标，Run 的显示名使用其 ID，避免目录名中
包含未选参数。

白名单包括 Project/Experiment 名称和已确认描述，Run 身份、状态、已选标量参数
和已选有限数值序列。任意配置、工作目录、原始日志、错误堆栈、源代码、文件
地址、环境和凭据均不属于契约。未知字段和非有限数值拒绝输入。读取只使用内建
元数据和 JSONL 解析器，不执行 sidecar 或用户脚本。

发布源 token 仅允许操作该来源的草稿和发布数据，不能登录浏览器、查看其他来源、
接受邀请或管理成员。数据库只保存 token 摘要。HTTP 客户端验证 HTTPS 证书，不
跟随重定向，也不从代理环境变量继承 HTTP 转发配置。

分批上传的草稿对 Viewer 不可见。批次按编号和摘要幂等；同编号不同内容返回 409。
提交时校验 Run 父级关系，比较 base version，然后原子切换版本。旧提交重试不
移动当前版本。单请求上限 2 MiB，单版本上限 20,000 个对象和 32 MiB，单批次每类
最多 500 个对象。单指标最多 2,000 点；所选原始指标文件超过 8 MiB 时明确拒绝，
不静默截断。

每个 Project 最多四个待提交草稿，每个来源最多 32 个，24 小时过期。
已知上传失败会取消草稿，断连或进程崩溃留下的草稿在之后的发布时清理。
保留当前及前一个版本的对象数据；更早的提交回执保留，用于幂等重试。

用户服务每 15 秒检查已有发布选择，只在白名单内容改变后上传新版本。新增对象、
参数或指标不会自动加入。停止发布增加 generation，使已启动草稿不能越过撤销
重新开启。后台刷新不会重启已停止发布；恢复需要 Owner 再次确认。

## 授权和邀请

v1 只有 Owner 和 Viewer。Editor、group grants、匿名链接、邮件投递和文件下载
暂不提供。邀请绑定接收者 Principal，七天过期；链接中的 ID 不是 bearer 凭据。
接受必须由接收者登录完成，事务内创建 Viewer grant。接收者可拒绝邀请或退出。

Viewer 可读取当前生效版本，不能修改 Project、访问私人文件、预览文件、启动
任务或调用 Owner 插件。现有 Workspace allowlist 不会因分享发生改变。接受邀请
和退出分享使用显式资源授权，不使用“所有 POST 都需要全局写角色”的规则。

未登录返回 401，无权获知资源存在时返回 404，已知资源上的管理权限不足返回
403。每次读取查询当前授权。停止发布或撤销 grant 后，提交完成后开始的新请求
拒绝访问。已经返回或正在传输的数据不能收回。

停止发布不会删除 Owner 的最后版本；其他 Viewer 不可读取它。原始 Workspace
离线或删除不自动删除已发布副本；Owner 应通过共享服务明确停止发布。

## HTTP 和界面

浏览器 API 使用 `/api/sharing/`，内部发布 API 使用 `/internal/sharing/`。
`/api/sharing/worker` 及其子路径路由到当前用户服务，其他共享 API 路由到网关。
所有用户身份头由代理生成。浏览器变更操作要求 Origin 与配置的 public origin
完全匹配。共享响应禁止缓存。公网入口使用 HTTPS，后端仅监听 loopback 或受控
Unix socket；Molab 不替代集群认证系统。

独立前端入口 `/shared` 和 `/publish` 不挂载私人 Workspace hooks，也不启动插件
发现。查询包含 Principal、共享 Project 和版本。身份改变、退出或认证失败时取消
请求并清除受保护缓存；授权读取失败时不继续展示旧数据。界面展示最后发布时间，
后台离线时保留最后成功版本。查看图表只使用发布的数字，不取原始文件。

## 实施与验收

| 批次 | 交付 | 验收 |
|---|---|---|
| P0 | 本契约、HTTP 模式、部署约束 | 安全语义可直接编写测试 |
| P1 | 独立服务、可信代理和固定 UID 启动 | 伪造身份和其他用户请求失败 |
| P2 | 授权、邀请、事务审计 | 并发接受和撤销正确 |
| P3 | 预览、发布、分批提交、刷新 | 不泄露未选字段，不产生半个版本 |
| P4 | Project/Experiment/Run/指标读取 | 不需要 Owner Workspace 权限 |
| P5 | 发布、邀请、只读页面 | 账号切换无旧数据回流 |
| P6 | 本地 HTTP 与 Linux 双 UID 验收、站点部署文档 | 内核隔离及代理配置得到单独验证 |

本地 HTTP 测试不能替代 Linux UID 验收，CI 的双 UID 测试也不能替代目标站点的
认证代理验收。上线前必须由站点验证 subject 来源、代理密钥隔离、socket/端口
可达性，以及数据库磁盘和备份恢复方式。

## Asset Sharing 首批实现

用户服务通过可选的 `asset_storage` 配置启用共享存储；未配置的部署继续只共享
元数据。根目录由管理员配置，并为每个 UID 预分配独立、只可遍历不可列出的
发布目录。网关不挂载该目录。服务启动时拒绝符号链接路径、不安全的父目录和
错误的目录所有者；文件打开使用 Linux `O_PATH`、`O_NOFOLLOW` 和逐层 `dir_fd`。

Owner 从现有 AssetRepository 中选择属于该 Project 的已登记文件，确认接收者、
字节大小和 SHA-256 摘要。接收者必须已接受 Project 邀请，并具有同一集群的管理员
绑定 UID；浏览器不能提交 UID、Linux 用户名、文件路径或任意存储 URL。
首批支持普通文件；目录资源需先打包为归档文件再登记。发布时流式复制并计算摘要，
拒绝符号链接、特殊文件、摘要变化和配置的大小上限，既不使用硬链接，也不继承源
文件的权限或扩展属性。后续替换原 Asset 槽位不会改变已发布副本。

`FilesystemPermissionBackend` 支持 POSIX ACL、NFSv4 ACL 和显式 Unix group。
自动模式优先检测原生 NFSv4，再选 POSIX；命令缺失或存储拒绝授权时明确报错。
POSIX ACL 清除副本继承的访问与默认 ACL，仅给接收者文件只读及目录遍历权限。
NFSv4 使用站点配置的身份域和 NSS 映射，替换继承 ACL，并读回核对实际授权。
Group 模式需管理员显式确认整个组的原生读取范围，且验证双方组成员身份；不会
作为 ACL 失败后的自动降级。所有操作仅针对新建发布副本。

共享数据库 v2 增加 Asset catalog，启动时从 v1 在事务内迁移。每条授权固定
来源、Project、Asset、接收者、集群、双方 UID、摘要和大小，状态依次为
`preparing`、`active`、`revoking`、`revoked`。授权发布使用准备/提交步骤，撤销与
对应审计处于同一事务。失败或崩溃的发布通过原子持久化的清理意图恢复；未提交
准备超过一小时会转入清理。

接收者下载先向控制面检查 Project 和 Asset 两个授权，再由其自己的用户服务以
自己的 UID 打开发布文件。网关和 Owner 服务均不代为向接收者读取文件。
移除成员、停止 Project 或禁用身份/发布源时，应用访问立即关闭且授权转为撤销中，
不会因稍后重新邀请或发布而恢复旧文件。Owner 用户服务后台删除副本后才确认
文件系统撤销；离线期间界面保留“撤销中”。已下载内容及已打开的文件描述符无法
追回。禁用来源后，其凭据只保留清理自身副本的能力，不再允许发布或下载。

Collaborative Workspace、Editor、直接目录共享和跨集群数据传输仍属后续阶段。
